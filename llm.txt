# eap-order - LLM Context

> Port 8080 | Context path `/eap-order`

## Ownership

- HTTP BUY/SELL acceptance and market-sequence allocation.
- Append-only order lifecycle event store.
- Transactional Order integration outbox.
- Durable `TradeExecutedEvent` inbox and idempotent command-side application.
- Rebuildable `orders_current` query projection, audit, and replay.
- TDA auction bid entry plus auction session/result views.

Order does not own Wallet balances, matching, the authoritative trade fact, or cross-service completion state.

## Current Write Flow

```text
POST /bid/buy or /bid/sell
  -> OrderSubmissionRequestedV1 + OrderSubmitted outbox
  -> response status PENDING_WALLET_CHECK

OrderConfirmedEvent / OrderFailedEvent
  -> append reservation result to order stream

TradeExecutedEvent
  -> persist order_trade_execution_inbox
  -> claim trade_id in order_trade_applications
  -> append buyer/seller trade application events
  -> manual ACK after durable handling
```

If command state is not ready, the inbox reconciler retries locally. The query projection is not a prerequisite for applying a durable trade.

## TDA Flow

```text
auction bid HTTP -> direct AuctionBidSubmittedEvent publish -> Wallet
AuctionCreatedEvent / AuctionClearedEvent -> persist auction view + notify WebSocket clients
```

The auction bid publication currently bypasses the Order integration outbox. Auction result listeners catch processing exceptions, so local failure does not necessarily trigger RabbitMQ redelivery. Do not apply CDA reliability or capacity claims to TDA.

## RabbitMQ Consumers

| Queue | Handler |
| --- | --- |
| `order.orderConfirmed.queue` | reservation confirmation batch listener |
| `order.orderFailed.queue` | reservation failure listener |
| `order.tradeExecuted.queue` | durable trade inbox/application listener |
| `order.auctionCreated.queue` | create/update auction session view |
| `order.auctionCleared.queue` | apply auction result view and client notification |
